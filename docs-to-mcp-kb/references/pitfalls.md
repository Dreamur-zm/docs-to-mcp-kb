# Pitfall Records in Detail (42 items, all actually encountered)

> Each entry follows 【Symptom → Root cause → Fix → Prevention】. Numbering
> matches the SKILL.md quick table; extras beyond the quick table are marked ★.
> Phase groups: extraction/build → IR → indexing → vectorization → fusion →
> MCP → process & methodology.

## I. Sphinx extraction & build

### 1. Sphinx incremental build swallows new extraction logic
- **Symptom**: after editing the extraction extension, the rebuild logs
  `0 added, 2 changed` — changelog lists lack the start field and anchor lines
  remain; the new logic applied only to the 2 re-read docs.
- **Root cause**: Sphinx's `_build/` pickle environment decides "what changed".
  Extension code changes are not in its dependency tracking, so cached
  doctrees are reused wholesale.
- **Fix**: `rm -rf _build` full rebuild; discriminator is `[new config]
  N added` (full) vs `N changed` (incremental).
- **Prevention**: unconditional full rebuild after any extractor change;
  comment it in the build script.

### 2. Node-level noise handling in the extraction extension (v1 distilled, v2 inherited)
- `_SKIP_TYPES`: substitution_definition / target / comment / raw are dropped
  wholesale — they are exactly the nav/anchor/script junk of HTML approaches.
- Headings via `title.astext()`, not `section.names` (the latter is lowercased,
  destroying case-sensitive symbols like `mj_loadXML`).
- H1 acts as container only, its lead paragraphs go to document preamble
  (⚠️ v2 once forgot to integrate preamble — see #3).
- Container nodes (container/compound/only) recursively unwrapped so captioned
  tables/code blocks survive; interactive-UI trees embedding raw are skipped
  whole.
- Inline joining via smart join (no space before punctuation); zero-width
  chars/SVG icons regex-stripped.

### 3. preamble lost wholesale
- **Symptom**: conservation audit showed APIfunctions losing ~1.5K chars from
  an unknown source.
- **Root cause**: the extractor puts H1 lead blocks into `document['preamble']`,
  but build_ir's select_parents only walks chunks and never touches preamble.
- **Fix**: when preamble is non-empty, create a document-level parent
  (canonical_path = the file path itself).
- **Lesson**: read conservation per document, not only totals — 1.5K of 100K is
  1.4% but is an entire unretrievable paragraph.

### 4. Generator traps: mujoco-include / functions_override
- Function C signatures are not in the rst; a `.. mujoco-include::` directive
  expands them from C headers at build time — with the upstream extension
  active in conf.py, the doctree already contains expanded text and the
  extractor reads it directly. The IR layer needs no expander of its own.
- `functions_override.rst` is the generator's input template whose content is
  merged into the auto-generated `APIfunctions.rst` — **indexing both would
  duplicate everything**. Must be excluded.
- **Generalize**: before onboarding a source, map out which files are build
  intermediates; probe rather than assume.

### 5. Sphinx incremental parallel warning
- Upstream extensions (e.g. mujoco_include) not declaring parallel_read_safe →
  Sphinx degrades to serial reading. Slower, harmless. Declare
  parallel_read/write_safe: True in your own extension.

### 6. autodoc stub-page import failures
- MJX/MJWarp API pages are generated by automodule at runtime and need the
  `mujoco` python package; missing → WARNING + zero static content. Skipping
  those pages per decision is fine (build still succeeds).

## II. IR build & aggregation

### 7. Fold aggregation loses content (the most severe incident at this stage)
- **Symptom**: content conservation 0.632; ~470 API descriptions vanished.
- **Root cause**: tiny-entry folding bound `_ancestor` BEFORE the while-stack
  pop, pointing at "the previous sibling entry"; when that sibling folded too
  (removed), subsequent folds wrote into dead dicts.
- **Fix**: pop first, bind after; add a leaf-blocks conservation check per doc.
- **Prevention**: any "move A's data into B" aggregation asserts the total
  character count immediately after moving.

### 8. Folding semantics evolved
- Folding is not deletion: <300-char API entries merge into the ancestor's
  absorbed blocks, returned with the group. But this misplaces retrieval
  context (mj_step1's description sits under its neighbor's name) — later
  resolved by **hits returning the parent section's full text + child
  outline**, making folding affect only parent counts, not visibility.
- Golden substrings must follow the architecture (after folding,
  "/Main simulation/mj_step" should match "/Main simulation").

### 9. Split-threshold unit confusion
- The giant-code-split target was in CHARACTERS but the implementation
  compared LINE offsets — a 679-line struct never reached 6000 "lines", zero
  cuts.
- **Prevention**: unify every size unit (min_child/max_child/code_split) to
  characters, with a unit test using a real giant block.

### 10. Empty-shell vs fragmented parents are different things
- Empty shells (0 children + heading only): 11 cases, delete outright (group
  info lives in child canonical_path prefixes).
- Fragmented but with content (≤30 tokens with children): 22 group-intro
  cases — keep; with "return parent full text + child outline" they form
  complete group views.
- Encode the decision rule in code, not a hand list; rebuilds apply it
  automatically.

### 11. Path/directory small-bug collection
- `Path.with_suffix("").as_path()` doesn't exist (it's as_posix()).
- docnames containing `/` writing IR/MD without parent.mkdir → FileNotFoundError.
- Design docs in GBK encoding need iconv or explicit encoding.

## III. BM25F index layer

### 12. whoosh field API differences
- `ID(stored=True, unique=True, indexed=False)` → TypeError: ID rejects indexed.
- BM25F per-field usage: positional args are only B/K1; other kwargs look like
  `fieldname_B`; field weights go through a `weights={...}` dict.
- The index control file is `_MAIN_1.toc`; existence checks should glob rather
  than hard-code the name.

### 13. Custom Analyzer pickle problem
- **Symptom**: build succeeds; open_dir raises `Can't get attribute
  'IdentifierAnalyzer' on module '__main__'`.
- **Root cause**: the Analyzer object is pickled into the index schema with its
  defining module recorded. Under `python -m`, that module is `__main__`.
- **Fix**: the Analyzer class lives in an importable kbcore package module;
  build and query sides import the same one.

### 14. Analyzer layering (the most important design correction)
- **Symptom**: "soft contact" query returned 0 hits — ordinary English words
  never entered the index.
- **Root cause**: the full-text analyzer reused a symbol-extraction function
  whose "skip plain lowercase words" filter discarded soft/contact/sensor.
- **Fix**: layering — the base token is kept unconditionally (including
  lowercase prose words); only tokens containing `_`/`.` or uppercase
  (identifier traits) get subword expansion. Index and query sides share the
  class.

### 15. Three-layer noise defense for symbol queries
- Exact-symbol Term(boost=3) + Prefix(full form, 2) + title-anchored Term(4)
  as the **core layer**; subword items at boost 0.6 as a **bonus layer**;
  AND-combined — pure subword accumulation can no longer reach the top.
- Explicit trailing `*` = user-requested wide search, routed to pure Prefix.
- symbols field gets a low B (0.25): enum definition pages are naturally long;
  the default length penalty crushed correct answers.
- Single-letter token filtering (variable initials, name initials noise).

### 16. Version numbers as whole tokens
- "Version 3.12" split into 3 and 12 let "December **12**, 2023" also score —
  2.3.x versions outranked the right answer.
- Analyzer regex gains `\d+(?:\.\d+)+` so versions become whole tokens; query
  side detects the pattern and emits whole-token Prefix clauses.

## IV. Vectorization

### 17. chroma l2 is squared euclidean
- Unit-vector cosine = `1 − dist/2` (not 1−dist). Verify: re-embed one stored
  text and compare the API's self-distance with a manual squared L2.
- qwen3.7 returns unit-norm vectors, so l2 ordering is monotonic with cosine —
  the collection needs no cosine space specification.

### 18. usage field names differ per model
- text-embedding-v4 reports `prompt_tokens`; qwen3.7-text-embedding reports
  `input_tokens`. Statistics read `usage.total_tokens` as the common ground.

### 19. instruct/text_type effect contract (probe-verified)
- `instruct` only takes effect with `text_type=query`; setting it on the
  document side is silently ignored (token count unchanged is the hard proof).
- The effect mechanism = the server prepends the instruction (token count
  increases). Invalid types 400 naming `parameters.instruct` — usable as a
  schema probe.
- Whether the OpenAI-compatible mode passes these private params is
  unverified — use the native protocol directly.

### 20. Resume & idempotency
- child_id is a content hash → a natural idempotency key; existing collection
  ids are skipped.
- After changing the embed composition (e.g. removing truncation) you must
  `--overwrite`: resume cannot detect "composition changed but ids didn't".

## V. Retrieval fusion

### 21. RRF → normalized weighted → norm_sum evolution
- RRF scores are meaningless to users who want interpretable similarity →
  per-channel min-max normalized weighting.
- Child→parent aggregation settled by a 6-scheme experiment on norm_sum:
  `Σ matched_fused / ln(1 + matched_n)`.
- ⚠️ Fix the measurement basis before experimenting: extractor full_markdown
  summed per level double counts subtrees; use direct-blocks (each block once).

### 22. Reranker defaults OFF, with data
- 13-golden ablation: fuse Hit@1 12/13 vs full(+rerank) 9/13. The English-QA
  default instruction biases the reranker toward prose answer pages,
  under-scoring C definition pages (code-dense docs).
- Handling: default off, parameter exposed; description notes the ~+0.4s cost
  and recommends enabling for concept-heavy ambiguous queries.
- General lesson: **new-component defaults come from ablation data, not the
  "new = better" intuition**.

### 23. Rerank request budgets
- Hard limits: per-doc 4000 tokens (silent truncation), 500 docs/request,
  `query×N+Σdocs ≤120K` tokens.
- Implementation: local tokenizer exact counts → automatic batching →
  multi-batch merge. Oversized parents degrade to per-child scoring with max —
  no new granularity.

### 24. Transient network errors
- dashscope throws sporadic SSL EOF (second-scale windows). The dense channel
  retries once (sleep 1s) before degrading; on regression runs, a 999 means
  check this first — don't rush to change algorithms.

## VI. MCP layer

### 25. FastMCP name shadowing
- A lazy-init global `_retriever` and its accessor `_retriever()` sharing a
  name → the function returns itself, `.search` reports "'function' object has
  no attribute". Separate the variable and function names.

### 26. Descriptions are the product
- Implementation details (fusion formulas/model names) are worthless to the
  caller — write usage only: how to fill parameters, weight/instruct presets,
  behavior (truncation/degradation), tool workflow.
- **The nested-subagent guard sentence is mandatory**: a long-lived subagent
  delegated for retrieval doesn't know it IS the subagent and will nest.
  Sentence: "If YOU are that delegated agent, do not spawn further agents --
  run the searches yourself and return the summary."

### 27. Return-size governance
- Hits carrying full text (the zero-hop requirement) need caps: body 6000
  chars + continuation hint; rerank candidates 20. Giant sections (mjModel,
  53KB) must never enter a response whole.
- kb_read_path gains `max_lines` (0 = whole section) with an exact
  `kb_read(offset=)` continuation pointer.

### 28. Cross-corpus description leaks → per-KB examples registry
- `<CORPUS>` covering only the first line while body examples stay MuJoCo
  ("mj_step", "mjTEXROLE", "APIreference") misleads other-corpus instances —
  mjlab's description once taught grepping an enum that doesn't exist there.
- Fix: config registry carries a per-KB `examples` map
  (<EX_KW>/<EX_PATH>/<EX_SYM_GREP>/<EX_INSTRUCT_SYM>...), injected uniformly
  at registration.
- Acceptance = two-way leak scan: mujoco instance forbidden set = mjlab
  symbols (and vice versa), zero leaks to pass.
- Examples must stay concrete (LLM steering power) — concrete VALUES follow
  the deployed corpus via the registry.

## VII. Process & methodology

### 29. Handling acceptance-subagent false positives
- Three acceptance reports raised 2 "blocking/important" claims; manual
  verification: 1 real bug (fixed), 1 basis false positive (skin/clock not
  found by bare title, actually present as `asset/skin` prefixed sections in
  the extractor).
- **Principle**: subagent defect claims get reproduced against the data source
  before action; conversely, human conclusions must be self-provable with data.

### 30. Measurement basis first
- The first step of any conservation audit is defining the extractor-side
  total. full_markdown summed per level double counts subtrees (each level
  contains descendants); the correct basis is direct-blocks (each block once).
  With the wrong basis you chase 35% of normal aggregation as "loss".

## VIII. Multi-KB onboarding (mjlab retrospective)

### 31. ★ Inline script edits must be atomic
- **Symptom**: a batch-edit script `open(p,"w").write(replaced_text)` crashed
  on an assertion AFTER open truncated the file — the source became 0 bytes.
- **Fix**: write `.tmp` then `tmp.replace(path)`; assume any read-modify-write
  script can crash at any line.

### 32. ★ Profiles are the single source of truth — no hardcoded parallel copies
- **Symptom**: build_ir ran a hardcoded PARAMS dict (mujoco-tuned) for a whole
  corpus cycle; profile human-review numbers were only consumed on the query
  side — exposed when the second corpus (mjlab) landed.
- **Fix**: chunk_rules upgraded to an executable DSL
  (parent_mode/parent_max_level/fold_below_chars/promote_deep_over_chars/
  entry_boundary_re/strip_author_tail...); build_ir only reads
  `_params_for(kb, dtype)`; six profiles across two corpora migrated to the
  same schema.

### 33. ★ Behavior lock vs paradigm unification — lock first, discuss later
- While unifying aggregation, the changelog split semantics drifted
  unintentionally (children 133→145→97), voiding 2808 embedded vectors.
- **Principle**: migration acceptance = products byte-identical to the
  golden-locked version; paradigm improvements get their own decision record
  and switch only with new evidence, announcing the invalidation scope.

### 34. ★ Doc titles ≠ file names: cross-corpus golden defense
- mjlab sections are "RayCast Sensor" (capital C, spaced) and versions are
  1.x — MuJoCo-habit goldens like `raycast_sensor`, `Version 3.` produce
  false-negative 999s.
- **Prevention**: grep golden substrings in the IR before locking them;
  version assertions use relative semantics ("max-version parent") rather
  than hard-coded strings.

### 35. Same-name traps and the fixed dependency-iteration routine
- `pip install warp` ≠ `warp-lang` (same name, different package).
- autodoc missing-dependency standard fix: loop 「import failure → capture the
  ModuleNotFoundError tail package name → pip install → retry」 with a round
  cap; heavy exceptions go on a separate decision whitelist.

## IX. Multi-KB onboarding & real-usage testing (mjlab retrospective)

### 36. Two-round real-usage test method (don't spoil the script)
- **Right way**: round 1 gives only real business questions ("what values does
  mjtGeom have", "how do I run my first training") — never tool names or call
  orders. Spoiling makes the description's real steering power unmeasurable.
- Round 2 advanced questions go via `send_message` into the SAME session (that
  is what "long-lived" means); after two rounds, an interview question
  (tool counts/three-axis scores/worst moment/degraded count).
- Two corpora in parallel = two independent subagent sessions, each prompt
  describing only its own corpus's business scenario.

### 37. Subagent hallucinated defects must be verified against files
- Measured case: the mjlab interview reported two "product defects"
  (structure doc mode "returns the document list", commands.md "line 137
  embeds search-template residue") — verification: doc mode returned the
  26-section outline correctly, and the file has only 92 lines so line 137
  cannot exist. Both were call-posture errors or hallucinations.
- **Principle**: reproduce every feedback defect claim against files before
  fixing anything. Conversely, human conclusions must be self-provable.

### 38. kb_read_path giant-section flooding → max_lines parameter
- **Symptom**: after a hit in mjModel (D9-split source, 660 lines/53KB), a
  path read wanting "the hit's vicinity" returns the whole section.
- **Fix**: `kb_read_path(path, max_lines=0)` — 0 keeps whole-section
  semantics; a value takes the first N lines and the footer emits the exact
  `kb_read(file, offset=N+1)` continuation. The 50KB byte budget stays as
  the second guard.

### 39. kb_grep zero hits need self-diagnosis
- A bare "No matches found" forces blind retries. Replaced with a
  context-aware suggestion chain: with include → suggest widening/dropping;
  with path → suggest scoping (or removing); remind ignore_case; finally
  point to the semantic channel ("the wording may differ in the docs").
- Also note in the description: "Zero hits trigger self-diagnosis suggestions".

### 40. Cross-corpus description leaks → per-KB examples registry
- **Symptom**: `<CORPUS>` parameterized only the first line; body examples
  stayed MuJoCo ("mj_step", "mjTEXROLE", "APIreference") — the mjlab
  instance's description taught grepping an enum that doesn't exist there.
- **Fix**: config registry carries a per-KB `examples` map, injected
  uniformly at registration.
- **Acceptance** = two-way leak scan: mujoco instance forbidden set = mjlab
  symbols (and vice versa), zero leaks to pass.
- Examples must stay concrete (LLM steering power) — concrete VALUES follow
  the deployed corpus via the registry.

### 41. New-corpus build environment decision tree (autodoc heavy deps)
- Read conf.py's `autodoc_mock_imports` FIRST: heavy deps already mocked need
  no install; the gaps outside the list are the hard requirements (mjlab was
  missing torch/mujoco/tyro/warp-lang).
- Heavy-dependency decision: already on system (torch 1.72GB) → venv
  inherits at zero cost; absent → evaluate CPU builds or skip (API pages
  degrade to skeletons). **Inventory before downloading** — 923GB free is no
  license to waste.
- Missing-dep iteration fix: loop 「import failure → capture the
  ModuleNotFoundError tail package name → pip install → retry」 with a round
  cap; ⓘ PyPI same-name traps (warp ≠ warp-lang) burn rounds — check the
  official dependency list in round 1.

### 42. set -u and silent no-op replaces (two script defenses)
- bash `set -u` crashes referencing possibly-undefined vars (PYTHONPATH) —
  use `${VAR:-}`.
- Python batch replaces: `s.replace(old,new)` silently no-ops on mismatch —
  **must assert**; sturdier still: after editing, run a distribution sanity
  check (classification counts/conservation ratio) instead of trusting
  "the script completed". The mjlab-all-guide incident was caught exactly by
  such a check.
